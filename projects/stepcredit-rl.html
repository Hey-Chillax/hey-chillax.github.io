Motivation动机Motivation

In a long-horizon agent task the reward arrives once, at the end: an ALFWorld household task either succeeds within 20 actions or fails. GRPO gives every step of a trajectory the same advantage, so a decisive action and a wasted one are pushed in the same direction, and the agent cannot tell which steps mattered. This project uses StepCredit-RL: steps taken from the same environment state in different trajectories are grouped, each step's relative advantage is computed from what followed it, and the result is added to the episode-level advantage — no critic and no extra rollouts.

长程 Agent 任务的奖励只在最后出现一次：ALFWorld 的家务任务要么在 20 步内完成，要么失败。GRPO 给一条轨迹的每一步相同的优势，关键动作和白费的动作被推向同一个方向，Agent 分不清哪一步重要。本项目采用 StepCredit-RL：把不同轨迹中相同环境状态下的步骤归为一组，按后续回报计算每一步的相对优势，再与整局优势相加，无需 critic，也无需额外 rollout。

Around it I built the whole pipeline — expert demonstrations, SFT, multi-turn RL and paired evaluation — and used it to answer practical questions: how much SFT and RL each contribute, when RL stops paying off, and whether denser rewards or more updates per rollout batch help.

围绕它，我搭建了专家示范 → SFT → 多轮 RL → 配对评测的完整流程，并用它回答几个实际问题：SFT 和 RL 各贡献多少、RL 什么时候不再划算、更稠密的奖励或每批 rollout 多更新几次有没有用。

Pipeline流程Pipeline

  1. Expert demonstrations. ALFWorld's built-in planner expert plays the 3,553 training games and solves 2,145 (60.4%) within 20 steps. Every step of a solved game becomes an SFT example whose prompt is token-identical to the one the RL rollout builds: 22,810 examples in total. The expert almost never solves the two-object task (55 of 813 games).
  2. SFT on the expert's tool calls: one epoch, 356 steps, about 1.4 hours; the loss covers only the tool calls.
  3. Multi-turn agentic RL. Each agent step — one LLM call plus one tool call — is a training sample of its own, so the context does not grow with the episode. 16 tasks × 8 rollouts per step, with asynchronous vLLM rollouts.
  4. Paired evaluation. Greedy validation records the result of every task, and two runs are compared on the same tasks with an exact McNemar test.
  1. 专家示范。ALFWorld 内置的规划专家玩 3,553 个训练游戏，20 步内解出 2,145 个（60.4%）。解出游戏的每一步都生成一条 SFT 样本，prompt 与 RL rollout 构造的 prompt 逐 token 一致，共 22,810 条。专家几乎解不出双物体任务（813 个里只有 55 个）。
  2. SFT：在专家的工具调用上训练 1 轮，356 步，约 1.4 小时；只在工具调用上计算 loss。
  3. 多轮 Agentic RL。每个 Agent 步（一次 LLM 调用加一次工具调用）是一条独立的训练样本，上下文不会随步数增长。每步 16 个任务 × 8 条 rollout，vLLM 异步 rollout。
  4. 配对评测。贪心解码验证，记录每个任务的结果；两次运行在同一批任务上做精确 McNemar 检验。

How StepCredit-RL assigns creditStepCredit-RL 如何分配信用

A step's advantage has two parts: an episode-level term — how the episode ended compared with the task's other rollouts — and a step-level term — how things went after this action compared with other actions taken from the same state. Identical states are found by hashing the environment observation, so the groups come for free from rollouts that already exist.

每一步的优势由两部分组成：整局项，即这局的结局与同一任务其他 rollout 相比的好坏；步级项，即这个动作之后的结果与从同一状态出发的其他动作相比的好坏。相同状态通过对环境观察做哈希找到，分组直接来自已有的 rollout，不需要额外采样。

Four updates per rollout batch每批 rollout 更新 4 次

At step 100, four updates reach 76.4% / 69.4% against 51.4% / 52.2% for one update — about where one update stands at step 150 (72.1% / 66.4%). Four updates lead at every validation from step 10 to step 100, and the run finishes in 16.4 hours, while one update needs about 29 hours to reach step 150.

第 100 步时，4 次更新达到 76.4% / 69.4%，1 次更新为 51.4% / 52.2%，大约相当于 1 次更新第 150 步的水平（72.1% / 66.4%）。从第 10 步到第 100 步，每一次验证都是 4 次更新领先；整个训练用时 16.4 小时，而 1 次更新到第 150 步约需 29 小时。

HotpotQA search agent and reward shapingHotpotQA 搜索 Agent 与奖励设计

  • EM reward: exact match rises from 46.2% to 54.5% in 200 steps (F1 0.603 → 0.681). The step-0 baseline is my own measurement; in this setup the first turn always searches with the original question.
  • Shaped reward (training only; validation still reports EM): an exact answer earns 1; a wrong but given answer earns 0.3 × token F1, plus 0.1 if the retrieved passages contain the answer, so at most 0.4 and an exact answer is always best; no partial credit without an <answer> tag; −0.05 for each repeated query, at most four times.
  • Outcome: repeated queries fall from 0.123 to 0.036 per question (−71%) and all-failed groups from 27% to 4%, with the same answer rate (94.3% vs 94.4%) and no sign of F1 farming. EM ends at 53.1% vs 54.5%: on the same 1,000 questions, 35 are answered correctly only by the shaped run and 49 only by the EM run, McNemar p = 0.16.
  • EM 奖励：200 步内 EM 从 46.2% 升到 54.5%（F1 0.603 → 0.681）。第 0 步的基线是我自己测的；这个设置下，第一轮总是先用原问题检索。
  • 稠密奖励（只改训练奖励，验证仍报 EM）：精确答对得 1 分；作答但答错得 0.3 × token F1，检索段落含答案再加 0.1，最多 0.4 分，精确答对永远最优；没有 <answer> 标签不给部分分；每次重复查询扣 0.05，最多扣 4 次。
  • 结果：每题重复查询从 0.123 降到 0.036（−71%），全错组从 27% 降到 4%，作答率不变（94.3% 对 94.4%），也没有刷 F1 的迹象。EM 最终为 53.1% 对 54.5%：同一批 1,000 题中，只有稠密奖励答对的 35 题，只有 EM 奖励答对的 49 题，McNemar p = 0.16。

Analysis分析Analysis

SFT lays the floor; RL covers what the demonstrations missSFT 打底，RL 补上示范覆盖不到的部分

About two hours of SFT, including data generation, take success from 7.1% / 2.2% to 67.1% / 67.2% and shorten the average episode from 19 to 14 steps. RL then adds 31.5 / 26.8 points, and the largest gain is on the two-object task the expert almost never solves (29% / 24% → 96% / 94%): RL learns behaviour that is not in the demonstrations rather than only sharpening it. These numbers are not comparable with pure-RL results on ALFWorld, because the planner expert uses privileged PDDL information — extra supervision, not a better algorithm.

约 2 小时的 SFT（含数据生成）把成功率从 7.1% / 2.2% 提到 67.1% / 67.2%，平均每局步数从 19 降到 14。RL 再提高 31.5 / 26.8 个点，提升最大的是专家几乎解不出的双物体任务（29% / 24% → 96% / 94%）：RL 学到了示范之外的策略，而不只是放大已有行为。这些数字不能与 ALFWorld 上纯 RL 的结果直接比较，因为规划专家用到了 PDDL 的特权信息，属于额外的监督，不代表算法更强。

RL saturates because the group signal runs dryRL 饱和是因为组内信号枯竭

After SFT, validation barely moves past step 20. Once training success passes 90%, 95% of groups are all-success; with γ = 1 their advantage is exactly zero, so 28% of training steps update nothing (12 of the last 25) and entropy falls to about 0.005. The last 80 steps — about 11 hours — add almost nothing. Tracking the share of groups without signal is a cheap way to decide when to stop RL or switch to harder tasks. On HotpotQA, the same measurement shows 80–86% of groups without signal from the start.

SFT 之后，验证分在第 20 步后基本不动。训练成功率超过 90% 后，95% 的组全部成功；γ = 1 时这些组的优势恰好为 0，于是 28% 的训练步没有任何更新（最后 25 步里有 12 步），熵降到约 0.005。后 80 步约 11 小时几乎没有收益。统计「无信号组」的比例，是判断何时停止 RL、何时换更难训练题的低成本办法。同样的统计显示，HotpotQA 从一开始就有 80–86% 的组没有信号。

Seen vs unseen, and a single seedseen 与 unseen，以及单种子

On seen games StepCredit-RL wins clearly at step 200 (+12.1, p = 0.006), mostly on the two-object (22/24 vs 12/24) and cooling tasks (17/25 vs 11/25). On unseen games the final step is a tie (p = 0.88), but from step 160 to 190 StepCredit-RL stayed at 74.6–80.6% while GRPO stayed at 49.3–56.7%; GRPO happened to peak at step 200 just as StepCredit-RL dipped. A single seed is noisy — two runs of the same configuration differed by 16 points at step 50 — so I report the final step together with the late-stage mean and trust only gaps that hold across many validations.

seen 上 StepCredit-RL 在第 200 步明显领先（+12.1，p = 0.006），主要来自双物体（22/24 对 12/24）和冷却类任务（17/25 对 11/25）。unseen 在最后一步打平（p = 0.88），但第 160–190 步 StepCredit-RL 一直在 74.6–80.6%，GRPO 在 49.3–56.7%；第 200 步恰好 GRPO 冲高、StepCredit-RL 回落。单种子噪声很大，同一配置的两次运行在第 50 步差了 16 个点，所以我同时报告最后一步和后期均值，只相信在多次验证中都成立的差距。

More updates per rollout batch每批 rollout 多更新几次

With one update per step, the policy ratio is always 1 and the PPO clip never acts; with four updates, the clip has to be widened at the same time (to 0.2), otherwise the later mini-batches are almost entirely clipped. The change is stable — clip fraction about 0.1%, PPO KL about 0.001, entropy declining normally — but the policy drifts further from the reference (KL loss 0.84 vs 0.22), because a KL coefficient of 0.001 is a weak constraint.

每步只更新 1 次时，策略比值恒为 1，PPO 的 clip 不起作用；改成 4 次更新时，clip 必须同时放宽到 0.2，否则后几个 mini-batch 的 token 几乎全被裁掉。改动后训练稳定：clip 比例约 0.1%，PPO KL 约 0.001，熵正常下降。代价是策略离参考模型更远（KL loss 0.84 对 0.22），因为 0.001 的 KL 系数约束很弱。

What did not pay off收效不明显的尝试

  • Reward shaping did not raise EM. More signal (far fewer all-failed groups) did not turn into accuracy. A likely reason, not yet tested: partial credit narrows the gap between exact and near-miss answers, and entropy fell faster (0.12 vs 0.17), so the agent explored less. EM stays the main reward; the repeated-query penalty on its own is the natural next ablation.
  • Dynamic sampling — up to three rollout batches per step, training only on groups with signal — reaches 50% about 2.5× sooner in wall-clock time (56.4% / 56.7% at step 50, after 8 hours) but does worse per environment interaction (45.7% / 41.8% vs 57.9% / 56.0% at 15,360 trajectories). After about step 80 it became unstable: entropy rose from 0.01 to 0.30, and responses grew from about 27 to over 400 tokens of looping reasoning. It pays off only when environment interaction is cheap.
  • 稠密奖励没有提高 EM。信号变多了（全错组大幅减少），却没有转化为准确率。可能的原因（尚未验证）：部分分缩小了精确答对与差一点答对之间的差距，熵也下降得更快（0.12 对 0.17），探索变少。主奖励保留 EM；单独保留重复查询惩罚是下一步最自然的消融。
  • 动态采样（每步最多 3 批 rollout，只训有信号的组）按耗时到达 50% 约快 2.5 倍（8 小时、第 50 步即达 56.4% / 56.7%），但按环境交互量反而落后（同为 15,360 条轨迹时 45.7% / 41.8% 对 57.9% / 56.0%）。约第 80 步后训练失稳：熵从 0.01 升到 0.30，回答从约 27 token 膨胀到 400 多 token 的绕圈推理。只有环境交互便宜时它才划算。
