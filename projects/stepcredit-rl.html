In short要点
  • Expert SFT lifts ALFWorld success from single digits to 67%; 100 RL steps then reach 98.6% / 94.0% (seen / unseen). The two-object task, rare in the demonstrations, goes from about 27% to 95%.
  • Trained from the base model for 200 steps, the step-level advantage beats GRPO on seen games, 82.9% vs 70.7% (McNemar p = 0.006); late-stage means 82.3 / 76.7 vs 61.0 / 57.9.
  • Four mini-batch updates per step give about 1.5× sample efficiency at the same rollout cost.
  • A shaped reward cuts the search agent's repeated queries by 71% but does not raise exact match (p = 0.16), so exact match stays the main reward.
  • 专家 SFT 把 ALFWorld 成功率从个位数提到 67%，再经 100 步 RL 达到 98.6% / 94.0%（seen / unseen）。示范里很少的双物体任务从约 27% 提到 95%。
  • 从基座训练 200 步，步级优势在 seen 上胜过 GRPO：82.9% 对 70.7%（McNemar p = 0.006）；后期均值 82.3 / 76.7 对 61.0 / 57.9。
  • 每步改为 4 次 mini-batch 更新，同样的 rollout 下样本效率约 1.5 倍。
  • 稠密奖励让搜索 Agent 的重复查询减少 71%，但 EM 没有提升（p = 0.16），所以主奖励保留 EM。

Motivation动机

In a long-horizon agent task, the reward arrives once, at the end: an ALFWorld household task either succeeds within 20 actions or it does not. GRPO gives every step of a trajectory the same advantage, so a decisive action and a wasted one are pushed in the same direction, and the agent cannot tell which steps mattered. This project adopts a step-level relative advantage: steps taken from the same environment state in different rollouts of the same task are compared with each other, which refines credit assignment without a critic and without extra rollouts.

长程 Agent 任务的奖励只在最后出现一次：ALFWorld 的家务任务要么在 20 步内完成，要么失败。GRPO 给一条轨迹的每一步相同的优势，关键动作和白费的动作被朝同一个方向推，Agent 分不清哪一步重要。本项目采用步级相对优势：同一任务的不同 rollout 里，从相同环境状态出发的步骤互相比较，从而细化信用分配，不需要 critic，也不需要额外 rollout。

Around it I built the whole pipeline — expert demonstrations, SFT, multi-turn RL and paired evaluation — and used it to ask practical questions: how much SFT and RL each contribute, when RL stops paying off, and whether denser rewards or more updates per rollout help.

围绕它，我搭建了专家示范 → SFT → 多轮 RL → 配对评测的完整流程，并用它回答几个实际问题：SFT 和 RL 各贡献多少、RL 什么时候不再划算、更稠密的奖励或每批 rollout 多更新几次有没有用。

Pipeline流程

  1. Expert demonstrations. ALFWorld's planner expert plays the 3,553 training games and solves 2,145 (60.4%) within 20 steps. Every step of a solved game becomes an SFT example whose prompt is token-identical to the one the RL rollout builds: 22,810 rows. The two-object task is almost never solved by the expert (55 of 813 games).
  2. SFT on the expert's tool calls: 1 epoch, 356 steps, about 1.4 hours; loss only on the tool calls.
  3. Multi-turn agentic RL. Each agent step — one LLM call and one tool call — is its own training sample, so context does not grow with episode length. 16 tasks × 8 rollouts per step, with asynchronous vLLM rollouts.
  4. Paired evaluation. Greedy validation writes a record per task; two runs are compared on the same tasks with an exact McNemar test.
  1. 专家示范。ALFWorld 自带的规划专家玩 3,553 个训练游戏，20 步内解出 2,145 个（60.4%）。解出的每一步都生成一条 SFT 样本，prompt 与 RL rollout 构造的 prompt 逐 token 一致，共 22,810 条。专家几乎解不出双物体任务（813 个里只有 55 个）。
  2. SFT：在专家的工具调用上训练 1 轮，356 步，约 1.4 小时；只在工具调用上算 loss。
  3. 多轮 Agentic RL。每个 Agent 步（一次 LLM 调用加一次工具调用）是一条独立的训练样本，上下文不会随步数膨胀。每步 16 个任务 × 8 条 rollout，vLLM 异步 rollout。
  4. 配对评测。贪心解码验证，逐任务记录结果；两次运行在同一批任务上做精确 McNemar 检验。

Step-level relative advantage步级相对优势

The advantage of a step is the sum of a trajectory-level term (how the episode ended, relative to the other rollouts of the task) and a step-level term (how well things went after this action, relative to other actions taken from the same state). Identical states are found by hashing the environment observation, so the anchor groups come for free from rollouts that already exist.

每一步的优势是两项之和：轨迹级（这局的结局相对同一任务其他 rollout 的好坏）和步级（这个动作之后的结果，相对从同一状态出发的其他动作的好坏）。相同状态通过对环境观察做哈希找到，锚点分组直接来自已有的 rollout，不需要额外采样。

Four updates per rollout batch每批 rollout 更新 4 次

At step 100, four updates reach 76.4% / 69.4% against 51.4% / 52.2% for one update — about where one update stands at step 150 (72.1% / 66.4%). Four updates lead at every validation from step 10 to 100, and finish in 16.4 hours, while one update needs about 29 hours to reach step 150.

第 100 步时，4 次更新达到 76.4% / 69.4%，1 次更新是 51.4% / 52.2%，大约相当于 1 次更新第 150 步的水平（72.1% / 66.4%）。从第 10 步到第 100 步，每一次验证都是 4 次更新领先；它 16.4 小时跑完，1 次更新到第 150 步约需 29 小时。

HotpotQA search agent and reward shapingHotpotQA 搜索 Agent 与奖励设计

  • EM reward: 46.2% → 54.5% EM in 200 steps (F1 0.603 → 0.681). The step-0 baseline is our own measurement; this recipe always searches the original question first.
  • Shaped reward (training only; validation still reports EM): exact answer 1; wrong but answered 0.3 × token F1 + 0.1 if the retrieved passages contain the answer (at most 0.4, so an exact answer is always best); no partial credit without an <answer> tag; −0.05 per repeated query, at most four times.
  • Outcome: repeated queries 0.123 → 0.036 per question (−71%) and all-failed groups 27% → 4%, with the same answer rate (94.3% vs 94.4%) and no sign of F1 farming. EM 53.1% vs 54.5%: on the same 1,000 questions only one run is right on 35 vs 49, McNemar p = 0.16.
  • EM 奖励：200 步内 EM 46.2% → 54.5%（F1 0.603 → 0.681）。第 0 步的基线是我们自己测的；这个 recipe 第一轮总是先用原问题检索。
  • 稠密奖励（只改训练奖励，验证仍报 EM）：精确答对得 1 分；作答但答错得 0.3 × token F1，检索段落含答案再加 0.1（最多 0.4，精确答对永远最优）；没有 <answer> 标签不给部分分；每次重复查询扣 0.05，最多扣 4 次。
  • 结果：每题重复查询 0.123 → 0.036（−71%），全错组 27% → 4%，作答率不变（94.3% 对 94.4%），没有刷 F1 的迹象。EM 53.1% 对 54.5%：同一批 1,000 题上只有一方答对的是 35 对 49，McNemar p = 0.16。

Analysis分析

SFT lays the floor; RL covers what the demonstrations missSFT 打底，RL 补上示范覆盖不到的部分

About two hours of SFT, including data generation, take success from 7.1% / 2.2% to 67.1% / 67.2% and cut the average episode from 19 to 14 steps. RL then adds 31.5 / 26.8 points, and the largest gain is on the two-object task the expert almost never solves (29% / 24% → 96% / 94%): RL learns behaviour that is not in the demonstrations rather than only sharpening it. These numbers are not comparable with pure-RL results on ALFWorld, because the planner expert uses privileged PDDL information — extra supervision, not a better algorithm.

约 2 小时的 SFT（含数据生成）把成功率从 7.1% / 2.2% 提到 67.1% / 67.2%，平均每局步数从 19 降到 14。RL 再提高 31.5 / 26.8 个点，提升最大的是专家几乎解不出的双物体任务（29% / 24% → 96% / 94%）：RL 学到了示范之外的策略，而不只是放大已有行为。这些数字不能和 ALFWorld 上纯 RL 的结果直接比，因为规划专家用了 PDDL 的特权信息，属于额外的监督，不代表算法更强。

RL saturates because the group signal runs dryRL 饱和是因为组内信号枯竭

After SFT, validation barely moves past step 20. Once training success passes 90%, 95% of groups are all-success; with γ = 1 their advantage is exactly zero, so 28% of training steps update nothing (12 of the last 25) and entropy falls to about 0.005. The last 80 steps — about 11 hours — add almost nothing. Measuring the share of groups without signal is a cheap way to decide when to stop RL or switch to harder tasks. On HotpotQA the same measurement shows 80–86% of groups without signal from the start.

SFT 之后，验证分在第 20 步后基本不动。训练成功率超过 90% 后，95% 的组全部成功；γ = 1 时这些组的优势恰好为 0，于是 28% 的训练步没有任何更新（最后 25 步里有 12 步），熵降到约 0.005。后 80 步约 11 小时几乎没有收益。统计「无信号组」的比例，是判断何时停止 RL、何时换更难训练题的低成本办法。同样的统计在 HotpotQA 上显示，80–86% 的组从一开始就没有信号。

Seen vs unseen, and one seedseen 与 unseen，以及单种子

On seen games the step-level advantage wins clearly at step 200 (+12.1, p = 0.006), mostly on two-object (22/24 vs 12/24) and cooling tasks (17/25 vs 11/25). On unseen games the final step is a tie (p = 0.88), but from step 160 to 190 the step-level run stayed at 74.6–80.6% while GRPO stayed at 49.3–56.7%; GRPO happened to peak at step 200 just as the step-level run dipped. A single seed is noisy: two runs of the same configuration differed by 16 points at step 50. So I report the final step together with the late-stage mean, and only trust gaps that hold across many validations.

seen 上步级优势在第 200 步明显领先（+12.1，p = 0.006），主要来自双物体（22/24 对 12/24）和冷却类任务（17/25 对 11/25）。unseen 在最后一步打平（p = 0.88），但第 160–190 步步级优势一直在 74.6–80.6%，GRPO 在 49.3–56.7%；第 200 步恰好 GRPO 冲高、步级优势回落。单种子的噪声很大：同一配置的两次运行在第 50 步差了 16 个点。所以我同时报最后一步和后期均值，只相信在多次验证上都成立的差距。

More updates per rollout每批 rollout 多更新几次

With one update per step, the policy ratio is always 1 and the PPO clip never acts; with four updates, the clip has to be widened together (0.2), otherwise later mini-batches are almost entirely clipped. The change is stable — clip fraction about 0.1%, PPO KL about 0.001, entropy declining normally — but the policy drifts further from the reference (KL loss 0.84 vs 0.22), because a KL coefficient of 0.001 is a weak constraint.

每步只更新 1 次时，策略比值恒为 1，PPO 的 clip 不起作用；改成 4 次更新时 clip 必须一起放宽到 0.2，否则后几个 mini-batch 的 token 几乎全被裁掉。改动后训练稳定：clip 比例约 0.1%，PPO KL 约 0.001，熵正常下降。代价是策略离参考模型更远（KL loss 0.84 对 0.22），0.001 的 KL 系数约束很弱。

What did not work没有效果的尝试

  • Reward shaping did not raise EM. More signal (far fewer all-failed groups) did not turn into accuracy. A likely reason, not yet tested: partial credit narrows the gap between exact and near-miss answers, and entropy fell faster (0.12 vs 0.17), so the agent explored less. I kept EM as the main reward; the repeated-query penalty on its own is the natural next ablation.
  • Dynamic sampling — up to 3 rollout batches per step, training only on groups with signal — is about 2.5× faster to reach 50% in wall-clock time (step 50 at 8 hours: 56.4% / 56.7%), but worse per environment interaction (45.7% / 41.8% vs 57.9% / 56.0% at 15,360 trajectories). After about step 80 it became unstable: entropy rose from 0.01 to 0.30 and responses grew from about 27 to over 400 tokens of looping reasoning. It only pays off when environment interaction is cheap.
  • 稠密奖励没有提高 EM。信号变多了（全错组大幅减少），但没有转化为准确率。可能的原因（还没验证）：部分分缩小了精确答对和差一点答对之间的差距，熵也下降得更快（0.12 对 0.17），探索变少。主奖励保留 EM；只保留重复查询惩罚是下一步最自然的消融。
  • 动态采样（每步最多 3 批 rollout，只训有信号的组）按耗时到达 50% 约快 2.5 倍（8 小时、第 50 步就到 56.4% / 56.7%），但按环境交互量反而落后（同为 15,360 条轨迹时 45.7% / 41.8% 对 57.9% / 56.0%）。约第 80 步后训练失稳：熵从 0.01 升到 0.30，回答从约 27 token 膨胀到 400 多 token 的绕圈推理。只有环境交互便宜时才划算。

What I implemented我实现的部分

The training framework and task recipes are adapted from Agent-R1, and the step-level advantage follows GiGPO (see References). These are the parts I added:训练框架和任务 recipe 改编自 Agent-R1，步级优势沿用 GiGPO（见出处）。下面是我加的部分：

Expert SFT stage专家 SFT 阶段

A generator that plays the training games with the planner expert and writes one SFT row per step, with prompts checked token by token against the RL prompts; an SFT → RL script that runs both stages in one go.

用规划专家玩训练游戏、每一步写一条 SFT 样本的生成器，prompt 与 RL 的 prompt 逐 token 核对；一条命令跑完 SFT → RL 的脚本。

Shaped reward for the search agent搜索 Agent 的稠密奖励

Token-F1 partial credit, credit for retrieving the gold answer and a capped repeated-query penalty; every branch checked on CPU with a fake LLM and the real retriever, tokenizer and reward manager.

token F1 部分分、检索命中答案的证据分和有上限的重复查询惩罚；上线前在 CPU 上用假 LLM 加真实检索、tokenizer 和奖励管理器跑通了每个分支。

Dynamic sampling and a loop-aware step reward动态采样与循环感知步级奖励

Dynamic sampling rolls out extra batches and keeps only groups with a learning signal. The loop-aware reward gives no-op actions a small penalty inside the step-level advantage only, so success still dominates and all-failed groups get a signal; off by default and identical to the original when disabled, covered by 18 numeric tests and 10 tests on real ALFWorld games. Its training run has not been done yet.

动态采样：多 rollout 几批，只保留有学习信号的组。循环感知奖励：只在步级优势里给空转动作一个小惩罚，成败仍是主信号，全失败组也能得到信号；默认关闭，关闭时与原版逐项相同，有 18 项数值测试和 10 项真实 ALFWorld 游戏测试。它的训练实验还没有跑。

Paired evaluation and result tooling配对评测与结果工具

Per-task validation records, an exact McNemar test between two runs, export of offline W&B runs, and the scripts that build the result tables and figures.

逐任务的验证记录、两次运行之间的精确 McNemar 检验、离线 W&B 记录导出，以及生成结果表和图的脚本。

An environment leak that crashed long runs导致长训练崩溃的环境泄漏

Both 200-step runs crashed at step 60 with a full /tmp. Each ALFWorld environment copied a 35 MB planner library into /tmp and loaded it; the copy was deleted but stayed mapped, and dlclose could not unload it because of STB_GNU_UNIQUE symbols. I confirmed this through /proc/self/maps, replaced it with a per-process pool of library instances, and verified that observations, rewards and valid actions are identical to fresh instances.

两个 200 步作业都在第 60 步因 /tmp 写满而崩溃。每个 ALFWorld 环境都把 35 MB 的规划库复制到 /tmp 再加载，复制品被删除后仍被进程映射，又因为库里有 STB_GNU_UNIQUE 符号，dlclose 卸载不掉。我用 /proc/self/maps 证实了这一点，改为进程内的库实例池，并逐项核对观察、奖励和可选动作与全新实例完全一致。
